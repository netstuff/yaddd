# NOTES: как проводилось ревью

## Подход

1. Прочитал `SKILL.md` целиком — он задаёт три коммитмента (минимум зависимостей, строгая
   типизация, простой публичный API) и правило: при ревью перед мержем идти по чек-листу в
   `references/review-checklist.md`, а не импровизировать.
2. Прочитал `references/review-checklist.md` — использовал его разделы (Dependencies, Typing,
   Public API, Deprecation & compatibility, Code quality, Tests, Toolchain) как скелет ревью и
   как гарантию полноты: каждая находка привязана к пункту чек-листа, чтобы ничего не потеряться.
3. Прочитал `references/project-skeleton.md` — не для скелета проекта, а ради зашитых в него
   следствий стандартов: `ruff` с `target-version = "py314"` и правилами `UP` (легаси-алиасы
   `typing.Dict`/`Optional` — `UP006`/`UP007`), `mypy --strict` (в т.ч. `warn_return_any` —
   повлияло на решение сужать `Any` через `isinstance`), обязательный `py.typed`.

## Порядок прохода по коду

- Сначала Typing (самый жёсткий фильтр стандарта) — сразу выловило отсутствие аннотаций и
  легаси-`typing`.
- Затем Public API — исключения (голый `Exception`, нет chaining/`add_note`), keyword-only для
  булева аргумента, `__all__`/случайные публичные имена.
- Затем 3.14-специфику — module-level `CACHE` против free-threaded сборок, PEP 695 для алиаса.
- Затем Dead code / честность API — параметр `strict`, который ничего не делает.
- Затем Toolchain/Tests — неиспользуемый импорт `Optional` (`F401`), отсутствие тестов.
- В конце — minor: `open()` без `encoding`, порядок объявления алиаса, неоговорённый `Any`.

## Решения при переписывании (не вытекают из кода механически)

- **`strict` удалён**, а не реализован: для голого `json` нет честной семантики без схемы
  валидации. Проверка «верхний уровень — объект» сделана безусловной — это минимум, который
  проходит и `mypy --strict` (сужение `Any`), и здравый смысл. Схемная валидация отложена как
  отдельное дизайн-решение (potential optional-extra, lazy import — по разделу 1 стандарта).
- **Кэш — явный `@dataclass(slots=True) ConfigCache` вместо глобала**: стандарте разрешает кэш,
  только как implementation detail с честной документацией потокобезопасности; предпочтительнее
  «передавать состояние явно», что в free-threaded мире и сделано. Альтернатива (удалить кэш
  совсем) упомянута в review как допустимая по KISS.
- **Конфликт правил**: KISS говорил бы просто убрать кэш и `get_value`, но задача — переписать
  код с сохранением функциональности, поэтому функциональность сохранена, а риски локализованы.
